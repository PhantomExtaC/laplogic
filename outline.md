## 2. `web_app/` — React Frontend

A **Vite + React + TypeScript + Tailwind CSS v4** single-page application serving as the LapLogic dashboard. All data is consumed from static JSON files in `public/data/` (no backend API calls at runtime).

### 2.1 Configuration Files

| File | Purpose | Key Details |
|------|---------|-------------|
| `package.json` | NPM project definition | Name: `fanalytics`, React 19, react-router-dom 7, recharts 3, Tailwind CSS 4, lucide-react, clsx |
| `vite.config.ts` | Vite build configuration | Plugins: `@vitejs/plugin-react`, `@tailwindcss/vite` |
| `tsconfig.json` | Root TypeScript config | References `tsconfig.app.json` and `tsconfig.node.json` |
| `tsconfig.app.json` | App-level TS config | Targets ES2020, strict mode |
| `tsconfig.node.json` | Node-side TS config | For Vite config file |
| `eslint.config.js` | ESLint flat config | TypeScript-ESLint, react-hooks, react-refresh plugins |
| `index.html` | HTML shell | Title: "fanalytics", mounts `#root`, loads `src/main.tsx` |
| `.gitignore` | Web-app specific ignores | `dist/`, `node_modules/` |

## 3. `analytics_engine/` — Current ML Pipeline

The primary Python-based ETL and machine learning pipeline. Orchestrated by `main.py` with YAML-driven configuration.

### Top-Level Files

| File | Purpose |
|------|---------|
| `main.py` | **Pipeline orchestrator** — parses CLI args (`--profile prod\|lab`), loads YAML config, sets up logging, executes pipeline steps sequentially via subprocess. Steps: `clean_master.py` → `build_dataset.py` → `arena.py` |
| `README.md` | Detailed analytics engine documentation (435 lines) — architecture diagrams, pipeline flow, feature explanations, getting started guide, tech stack |

### 3.1 Configuration

| File | Purpose |
|------|---------|
| `config/base.yaml` | **Central pipeline configuration.** Defines: target variable (`won_race`), historical start year (2014), test split year (2024), active feature list (8 features), model hyperparameters (RF: 100 trees/depth 6, XGBoost: 200 trees/depth 4/lr 0.05), execution profiles (prod vs lab) |

**Key Config Sections:**
- `pipeline.target_variable`: `"won_race"` — binary classification target
- `features`: 8 active features: `grid`, `quali_delta_to_pole`, `team_momentum`, `driver_momentum`, `driver_overall_avg`, `driver_track_avg`, `driver_racecraft_index`, `tire_deg_index`
- `profiles.prod`: `fail_fast: false`, `export_json: true`, `log_level: INFO`
- `profiles.lab`: `fail_fast: true`, `export_json: false`, `log_level: DEBUG`

### 3.2 `data/` — Data Lake

Organized in a **Bronze → Silver → Gold** data architecture:

| Directory | Layer | Contents |
|-----------|-------|----------|
| `data/raw/` | **Bronze** | 15 raw Ergast/Kaggle CSV files + `master_historical.csv` (joined dataset). Files: `circuits.csv`, `constructors.csv`, `constructor_results.csv`, `constructor_standings.csv`, `drivers.csv`, `driver_standings.csv`, `lap_times.csv`, `pit_stops.csv`, `qualifying.csv`, `races.csv`, `results.csv`, `seasons.csv`, `sprint_results.csv`, `status.csv`, `master_historical.csv` |
| `data/clean/` | **Silver** | 4 cleaned/filtered CSVs: `clean_races.csv`, `clean_drivers.csv`, `clean_constructors.csv`, `clean_results.csv` |
| `data/features/` | **Gold (Features)** | 3 engineered feature CSVs: `mastery_matrix.csv`, `power_ratings.csv`, `track_profiles.csv` |
| `data/processed/` | **Gold (ML)** | 1 file: `model_training_matrix.csv` — the final training-ready dataset |
| `data/export/` | **Export** | 2 JSON files: `insights.json`, `tracks.json` (also exported to `web_app/public/data/`) |
| `data/cache/` | **Cache** | `fastf1_http_cache.sqlite` — FastF1 API response cache |

### 3.3 `src/` — Pipeline Source Code

#### 3.3.1 `src/ingestion/` — Data Collection (3 files)

| File | Function | Purpose | Input → Output |
|------|----------|---------|----------------|
| `bootstrap.py` | `bootstrap_historical_data(start_year=2000)` | **One-time setup.** Joins raw Ergast relational tables (races, results, drivers, constructors, pit_stops) into a single denormalized `master_historical.csv`. Engineers `total_race_pit_stops` metric. | `data/raw/*.csv` → `data/raw/master_historical.csv` |
| `bridge_seasons.py` | `bridge_gap()` | Fills the data gap between Kaggle static CSVs and the current season using the **Jolpica (Ergast) API** via FastF1. Implements exponential backoff retry logic for API rate limits. | Jolpica API → appends to `master_historical.csv` |
| `update.py` | `update_current_season()` | **Incremental updater.** Detects the latest round in the database, fetches only missing completed races from the current season via Ergast API. | Jolpica API → appends to `master_historical.csv` |

#### 3.3.2 `src/preprocessing/` — Data Cleaning & Transformation (2 files)

| File | Function | Purpose | Input → Output |
|------|----------|---------|----------------|
| `clean_master.py` | `clean_ergast_database()` | **Bronze → Silver transformation.** Cleans 4 raw CSVs: races (filter ≥2014, merge circuitRef), drivers (handle `\N` nulls, uppercase codes), constructors (select columns), results (coerce types, handle nulls). | `data/raw/*.csv` → `data/clean/clean_*.csv` |
| `build_dataset.py` | `build_training_matrix()` | **Silver → Gold transformation.** Assembles the ML training matrix by merging clean tables with engineered features. Dynamically reads active features from YAML config. Computes qualifying deltas from `qualifying.csv`. Merges mastery, power, and track features. | `data/clean/*.csv` + `data/features/*.csv` + `config/base.yaml` → `data/processed/model_training_matrix.csv` |

#### 3.3.3 `src/features/` — Feature Engineering (4 files)

| File | Function | Purpose | Key Metrics Generated |
|------|----------|---------|----------------------|
| `track_profile.py` | `generate_track_profiles()` | Engineers circuit fingerprints. Calculates avg pit stops per circuit, derives tire degradation index (1–5 scale via `pd.qcut`), classifies street vs permanent circuits. | `tire_deg_index` (1–5), `is_street` (0/1), `avg_pit_stops` |
| `power_rating.py` | `generate_power_ratings()` | Computes dynamic momentum metrics using **Exponential Moving Average (EMA, span=10)** with `.shift(1)` to prevent data leakage. | `team_momentum` (EMA of team points), `driver_momentum` (EMA of finishing position), `driver_racecraft_index` (EMA of positions gained) |
| `mastery.py` | `generate_mastery_matrix()` | Builds driver–track suitability matrix with hierarchical fallback: track-specific avg → street circuit avg → career avg → midpoint (10.5). | `driver_overall_avg`, `driver_track_avg`, `driver_street_avg`, `driver_high_deg_avg` |
| `generate_standings.py` | `generate_driver_standings()`, `generate_constructor_standings()` | Fetches live championship standings from Jolpica API via FastF1 Ergast client. Exports directly to `web_app/public/data/`. | → `driver_standings.json`, `constructor_standings.json` |

**Output Paths:**
- `track_profile.py` → `data/features/track_profiles.csv`
- `power_rating.py` → `data/features/power_ratings.csv`
- `mastery.py` → `data/features/mastery_matrix.csv`
- `generate_standings.py` → `web_app/public/data/driver_standings.json`, `constructor_standings.json`

#### 3.3.4 `src/evaluation/` — Model Evaluation (2 files)

| File | Function | Purpose |
|------|----------|---------|
| `arena.py` | `run_arena()` | **Model Arena.** Trains both Random Forest and XGBoost on pre-2024 data, evaluates race-by-race win prediction accuracy on 2024+ test set, compares against a "pole position = winner" baseline. Exports `arena_metrics.json` with champion model and accuracy stats. |
| `feature_ranking.py` | (script-level) | Diagnostic utility that prints feature importance breakdowns for both RF and XGBoost models. Not part of the automated pipeline. |

#### 3.3.5 `src/export/` — JSON Export Layer (5 files)

| File | Function | Purpose | JSON Files Generated |
|------|----------|---------|---------------------|
| `json_builder.py` | `build_json_exports()` | **Master export orchestrator.** Generates the calendar, points progression, driver form trends, structural insight snapshots, and track degradation data. Calls `weekend_builder` and `prediction_engine`. | `calendar.json`, `pointsProgression.json`, `driverTrends.json`, `insights.json`, `tracksDeg.json` |
| `weekend_builder.py` | `build_weekend_state(year)` | Fetches live FP2 telemetry data from FastF1 for the upcoming race. Extracts weather conditions, fastest sectors, and long-run pace data for every driver. Falls back to most recent completed race if FP2 hasn't occurred yet. | `weekend_state.json` |
| `prediction_engine.py` | `generate_predictions(year)` | **FP2-Enhanced Prediction Engine.** Uses exponential decay on long-run pace deltas to compute win probabilities. Falls back to 3-race historical momentum if FP2 data is unavailable. | `predictions.json` |
| `rf_prediction_engine.py` | `run_rf_predictions()` | **Random Forest Prediction Engine.** Trains an RF classifier on the processed training matrix, then infers win probabilities for upcoming race drivers using their latest mastery/power/track features. Includes a `DRIVER_MAP` translating FastF1 3-letter codes to Ergast references. | `predictions.json` (overwrites the one from `prediction_engine.py`) |
| `build_training_data.py` | `build_dataset()` | Historical FP2 data scraper. Loads FP2 sessions from 2023–2025 via FastF1, extracts long-run pace, calculates deficits, joins with race results. Uses `f1_cache/` for caching. | `f1_historical_training_data.csv` (in `web_app/public/data/`) |
