## Contract Discrepancies Found

### D1 — Evaluation Champion Conflict
- **`evaluation_metrics.json`** names **XGBoost** as champion (RF 48.3%, XGB 51.7%, baseline 60%, 60 races)
- **`arena_metrics.json`** names **Random Forest** as champion (RF 62.5%, XGB 45.8%, no race count)
- **Frontend `EvaluationCard.tsx`** reads fields `rfAccuracy`, `rfTop3Coverage`, `isOutperforming` — **none of which exist** in either JSON file
- **Resolution:** Created unified `evaluation.json` with a `conflictWarning` field. Adapter reads both legacy files and flags the conflict. UI shows a visible "Conflicting Evaluation Runs" warning.

### D2 — Driver Type vs Actual JSON
- **Type expects** `dateOfBirth: string`, `age: number`, `raceFinishes: number`, `poles: number`
- **JSON supplies** `polePositions` (not `poles`), no `dateOfBirth`, no `age`, no `raceFinishes`
- **JSON has extra fields** not in type: `seasons`, `yearsActive`, `raceEntries`, `winRate`, `podiumRate`, `poleRate`, `fastLapRate`, `pointsPerEntry`, `championshipYears`, `careerPoints`
- **Resolution:** Adapter maps `polePositions` → `poles`, marks `dateOfBirth`/`age`/`raceFinishes` as nullable (`null`), preserves extra fields.

### D3 — Track Type vs Actual JSON
- **Type uses** `corners: number` — **JSON supplies** `turns: number`
- **Type uses** `layout: string` — **JSON supplies** `layoutImage: string`
- **Type expects** `laps: number`, `drsZones: number` — **JSON has neither**
- **`lapRecord.milliseconds`** holds values like 69.593 (these are seconds, not milliseconds). e.g., "1:09.593" → 69.593
- **Resolution:** Adapter maps `turns` → `corners`, `layoutImage` → `layout`, renames `milliseconds` → `lapTimeSeconds`. `laps` and `drsZones` default to `null`.

### D4 — Standings `driverNumber` Type Mismatch
- **Type declares** `driverNumber: string`
- **`driver_standings.json`** supplies `driverNumber` as a **number** (e.g., `1`, `4`, `44`)
- **Resolution:** Adapter coerces to string.

### D5 — Weather Type Duplication
- **`weather.ts`** uses `airTemperature`, `trackTemperature`
- **`weekend.ts`** uses `airTemp`, `trackTemp`
- **`next_race.json`** uses `airTemperature`, `trackTemperature`
- **`weekend_state.json`** uses `airTemp`, `trackTemp`
- **Resolution:** Unified to `airTemp`/`trackTemp` in domain types. Adapters normalize both shapes.

### D6 — Duplicate Race/Calendar Types
- **`race.ts`** exports `Race` (with `trackId`, `country`)
- **`calendar.ts`** exports `RaceEvent` (with `grandPrix`, `date`, `sprintWeekend`, `status`)
- **`calendar.json`** matches `RaceEvent` shape; `Race` is only used by `Calendar.tsx` with manual field mapping
- **Resolution:** Unified into single `RaceEvent` domain type. Deprecated `Race`.

### D7 — next_race.json vs calendar.json Conflict
- **`next_race.json`** says next race is **Belgium Round 12 on 2026-07-26**
- **`calendar.json`** first upcoming entry is **Italy** (later round)
- **`weekend_state.json`** references **Italy**
- **Resolution:** `nextEvent()` logic derives from `calendar.json` only. `next_race.json` is deprecated but not deleted.

### D8 — Predictions Missing Event Identity
- **`predictions.json`** is a bare array with no event ID, model ID, stage, or generation timestamp
- **Driver IDs** use 3-letter abbreviations (`nor`, `ver`, `ham`) which differ from `drivers.json` IDs (`norris`, `max_verstappen`, `hamilton`)
- **Probabilities** sum to ~0.984 over 10 drivers (not 1.0)
- **Resolution:** Adapter wraps in `{meta, data}` envelope. Coverage computed and displayed. Driver registry maps abbreviations to canonical IDs.

### D9 — EvaluationCard Schema Mismatch
